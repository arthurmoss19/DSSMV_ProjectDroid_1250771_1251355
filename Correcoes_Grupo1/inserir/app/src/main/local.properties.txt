=======================================================================
 FICHEIRO: Project/local.properties  (NÃO vai para o Git)
 ONDE:    há uma linha "RESTDB_URL" e outra "RESTDB_KEY"
=======================================================================

O que tens hoje:

    RESTDB_URL=https://<seu-nome-da-base>.restdb.io/
    RESTDB_KEY=<AQUI É A CHAVE DO RESTDB>

O problema: o endereço tem "<" e ">" no meio, e isso NÃO é um endereço
válido. Como o Retrofit lê este valor ao construir o cliente, rebenta
com "java.lang.IllegalArgumentException: Invalid URL host" no instante em
que tentas entrar — a app fecha antes sequer de dar o erro de rede.

Como não vamos pôr chaves agora, basta trocar a linha do endereço por um
valor válido, por exemplo (não é uma chave, é só um endereço de exemplo):

    RESTDB_URL=https://triptrail-demo.restdb.io/

(Em alternativa, deixa a linha em branco — "RESTDB_URL=" — e o
app/build.gradle.kts usa sozinho o valor por omissão, que também é válido:
"https://triptrail-xxxxxx.restdb.io/".)

A chave troca-a também por um valor simples, para não deixar um acento no
meio (o OkHttp recusa cabeçalhos com caracteres fora do ASCII):

    RESTDB_KEY=X

=======================================================================
 NOTAS:
 * Isto não põe nenhuma chave a sério: só garante que o endereço tem uma
   forma aceitável para o Retrofit não rebentar. Quando tiveres as chaves
   verdadeiras, voltas a pôr o teu endereço do restdb.io.
 * Do resto do local.properties só interessa mesmo o "sdk.dir", que já está
   certo: C:\Users\pedro\AppData\Local\Android\Sdk
 * Este ficheiro NUNCA vai para o repositório (está no .gitignore).
 * Se um dia quiseres correr contra o RESTDB a sério, acrescenta também:
       USE_MOCK_DATA=false
   sem isso fica a TRUE e a app continua a usar os dados de demonstração.
